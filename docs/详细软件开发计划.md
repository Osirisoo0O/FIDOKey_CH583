## 阶段二：核心加密与安全模块

### 2.1 硬件随机数生成器
- [ ] 初始化CH583的TRNG（真随机数发生器）
- [ ] 实现`get_random_bytes()`函数，用于生成：
  - 私钥种子
  - 挑战值随机数
  - 加密盐值

### 2.2 AES-128加密/解密
- [ ] 确认蓝牙库初始化完成后再调用AES模块
- [ ] 使用`LL_Encrypt()`和`LL_Decrypt()`函数接口
  ```c
  // 加密示例
  uint8_t key[16] = {...};
  uint8_t plaintext[16] = {...};
  uint8_t ciphertext[16];
  LL_Encrypt(key, plaintext, ciphertext);  // 加密
  
  // 解密示例
  uint8_t decrypted[16];
  LL_Decrypt(key, ciphertext, decrypted);  // 解密
  ```
- [ ] **注意**：AES加解密数据必须保证16字节对齐

### 2.3 芯片唯一ID读取
- [ ] 读取CH583的唯一ID（`UID`寄存器）
- [ ] 将UID作为AES加密密钥的一部分，增强私钥存储安全性

### 2.4 ECDSA P-256实现
> **重要提示**：CH583 SDK**未内置**ECDSA算法库，需要自行移植。

- [ ] **方案A：移植Mbed TLS**
  - 下载Mbed TLS源码，裁剪至仅保留：
    - `ecp.c`（椭圆曲线运算）
    - `ecdsa.c`（签名/验签）
    - `sha256.c`（哈希）
    - `bignum.c`（大数运算）
  - 预计占用Flash：~30-50KB，RAM：~4-8KB
  - 需实现`mbedtls_platform_entropy_poll()`调用硬件TRNG

- [ ] **方案B：移植micro-ecc**
  - 更轻量级，专为嵌入式设计
  - 仅需`uECC.c`和`uECC.h`
  - 支持secp256r1（P-256）曲线
  - 预计占用Flash：~10-20KB，RAM：~2-4KB

- [ ] **实现核心函数**：
  ```c
  // 生成密钥对
  int generate_keypair(uint8_t *private_key, uint8_t *public_key);
  
  // ECDSA签名（SHA-256哈希后签名）
  int ecdsa_sign(const uint8_t *private_key, const uint8_t *hash, 
                 uint8_t *signature_r, uint8_t *signature_s);
  
  // ECDSA验签（可选，用于自测）
  int ecdsa_verify(const uint8_t *public_key, const uint8_t *hash,
                   const uint8_t *signature_r, const uint8_t *signature_s);
  ```

### 2.5 安全存储方案设计
- [ ] **存储布局**：
  | 地址范围 | 大小 | 内容 |
  |---------|------|------|
  | DataFlash起始 | 16字节 | 主密钥（AES加密用） |
  | +16字节 | 16字节 | 盐值 |
  | +32字节 | 可变 | 加密后的私钥（每个凭证~100字节） |
  | +... | ... | 凭证计数器等元数据 |

- [ ] **私钥加密存储流程**：
  1. 读取芯片UID + 固定盐值 → 通过AES-128派生存储密钥
  2. 生成ECDSA密钥对后，用存储密钥加密私钥
  3. 加密后的私钥写入DataFlash
  4. 每次使用时，从Flash读取密文，解密后使用

- [ ] 实现`secure_store_write()`和`secure_store_read()`

### 2.6 CBOR编解码器
- [ ] FIDO2 CTAP协议使用CBOR（Concise Binary Object Representation）编码
- [ ] 移植轻量级CBOR库（如`tinycbor`或`cbor-lite`）
- [ ] 实现CTAP请求解析和响应封装的CBOR辅助函数

## 阶段三：FIDO2 CTAP协议实现

### 3.1 CTAP协议框架
- [ ] 参考CTAP 2.3规范（2026年2月发布）
- [ ] 实现`CTAPHID`命令解析器，支持以下命令：
  | 命令码 | 名称 | 说明 |
  |-------|------|------|
  | 0x10 | `CTAPHID_MSG` | 加密消息通道 |
  | 0x11 | `CTAPHID_CBOR` | CBOR编码请求（主要） |
  | 0x12 | `CTAPHID_INIT` | 连接初始化 |
  | 0x13 | `CTAPHID_PING` | 保活检测 |
  | 0x14 | `CTAPHID_CANCEL` | 取消操作 |
  | 0x3F | `CTAPHID_ERROR` | 错误响应 |

### 3.2 `GetInfo`命令实现
- [ ] 这是CTAP最基础的命令，主机首先调用
- [ ] 返回认证器能力信息：
  ```cbor
  {
    "versions": ["FIDO_2_0", "FIDO_2_1", "FIDO_2_3"],  // 支持CTAP 2.3
    "extensions": [],
    "aaguid": <16字节认证器GUID>,
    "options": {
      "uv": false,           // 不支持用户验证
      "up": true,            // 支持用户存在
      "rk": true,            // 支持可驻留密钥
      "clientPin": false,    // 暂不支持PIN（可后续扩展）
      "largeBlobs": false
    },
    "maxMsgSize": 1200,
    "transports": ["usb"]    // 或 ["usb", "ble"]
  }
  ```

### 3.3 `MakeCredential`（注册）命令
- [ ] **请求解析**：
  - 解析`clientDataHash`（32字节）
  - 解析`rp`（依赖方信息）
  - 解析`user`（用户信息）
  - 解析`pubKeyCredParams`（支持的算法列表）
  - 解析`excludeList`（已注册凭证排除列表）
- [ ] **处理逻辑**：
  1. 检查`excludeList`，若凭证已存在则返回错误
  2. 生成新的ECDSA P-256密钥对
  3. 将私钥加密后存入安全存储区
  4. 构建认证器数据（`authData`）
  5. 生成凭证ID（可基于公钥哈希）
  6. 生成签名：对`authData + clientDataHash`进行ECDSA签名
  7. 构建并返回`Attestation Object`
- [ ] **认证方式**：可采用"无认证"（`none`）或"基本认证"（`packed`）

### 3.4 `GetAssertion`（登录/断言）命令
- [ ] **请求解析**：
  - 解析`rpId`
  - 解析`clientDataHash`
  - 解析`allowList`（允许的凭证ID列表，可选）
  - 解析`options`（如`up`要求）
- [ ] **处理逻辑**：
  1. 若`allowList`为空，遍历所有已存储凭证
  2. 若`allowList`非空，仅匹配列表中的凭证
  3. 等待用户按键确认（`up`要求）
  4. 用对应私钥对`authData + clientDataHash`签名
  5. 返回签名结果和凭证信息

### 3.5 凭证管理
- [ ] 实现凭证的增删改查：
  - `credential_add()`：存储新凭证
  - `credential_find()`：按凭证ID查找
  - `credential_list()`：列出所有凭证（用于`GetInfo`）
  - `credential_delete()`：删除凭证（支持`CredentialManagement`扩展）
- [ ] 凭证数据结构：
  ```c
  typedef struct {
      uint8_t credential_id[64];
      uint8_t credential_id_len;
      uint8_t rp_id_hash[32];
      uint8_t user_id[64];
      uint8_t user_id_len;
      uint8_t private_key_encrypted[96];  // AES加密后的私钥
      uint8_t public_key[64];             // 未压缩格式
      uint32_t sign_count;                // 签名计数器
  } fido_credential_t;
  ```

### 3.6 签名计数器
- [ ] 每次`GetAssertion`成功后，递增签名计数器
- [ ] 将计数器随签名一起返回（防止重放攻击）
- [ ] 持久化存储到Flash（每次更新时写入）

### 3.7 （可选）BLE CTAP传输
- [ ] 实现BLE GATT特性上的CTAP协议封装
- [ ] 处理BLE MTU分片和重组
- [ ] 参考CTAP 2.3的BLE混合传输通道规范
